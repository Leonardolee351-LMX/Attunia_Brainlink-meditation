# Attunia — Progress Brief

## Background（先讲人，再讲产品）

晚上七点，电脑合上了，通勤开始了——但脑子没有合上。未回的消息、没推完的文档、会上没说出口的那句，像没关干净的标签页，在地铁晃动里反复弹出。人已经离开工位，情绪还停在「未完成」：说不清是焦虑还是亏欠，只是安静不下来，也还没资格叫休息。

早上九点，人已经坐进工位，咖啡也喝了——但状态还没到岗。日历第一格在闪，身体仍像停在昨晚的余震里；手指放在键盘上，却迟迟进不了第一个真正的任务。不是懒，是「还没准备好工作」的那段空白：上一夜没收尾，这一天却已经要求启动。

工作进行到半途，更难被自己看见。文档开着，光标偶尔移动，注意其实已经漂到别处；或者会开完一场接一场，肩颈还挂着高唤醒，人却仍对自己说「再撑一下」。走神与过度疲劳常常没有戏剧性崩塌，只有不被意识到的损耗——直到效率掉下去、情绪毛躁起来，才后知后觉。

这三段落差——**下班后的未完成感、上班后的未就绪感、工作中未被察觉的走神与过劳**——共同指向一种潜在的心理「没收尾」：状态切换的真空里，人悬着；工作进行时，人又可能在空转或过载。Attunia 正是为这类 Work–Life 节奏里的真实落差而设计的 Soft Healthcare 调节产品（非医疗诊断或治疗）。

## Pitch（产品是什么 · Soft Healthcare）

报名方向：**Soft Healthcare（生命健康 / 软医疗）**——用可穿戴与 AI 做**日常身心状态调节与福祉**，明确不是诊断、处方或医疗器械产品。

**Attunia** 面向 **Work–Life Balance**，在上述落差高发的时刻做调节式介入：

1. **「工作 ↔ 休息」切换的真空期**——上下班通勤、刚收工 / 刚开工、会后空档：上一状态已结束、下一状态未就绪，需要被接住并调律。  
2. **工作进行中的走神与超负荷**——人还在工位上，注意飘散或被连续任务压到过载：需要短时「回笼专注」或「卸压」，而不是硬扛到下班。

产品以**脑电数据采集**为基础，给出更贴合个人日常节奏（tempo）的短时练习与陪伴，帮用户为接下来的工作 / 休息 / 挑战打底。对话由 Agent **Tuno** 完成；需要多人视角时走 Multi-Agent 会诊（只拼已有疗法目录）。合规：显著免责声明 + 危机识别转介；原始脑电不外传、不进外部 LLM。

### 用户场景

- **工作–休息切换的真空期**：下班路上的未完成感、到家未真正放松前；早上进工位尚未就绪——潜在情绪不安或需要消化上一场张力。  
- **工作中的走神**：该专注时注意飘走，需要轻量「收心 / 回笼」，而不是长篇冥想。  
- **工作中的超负荷 / 过度疲劳**：连续会议、信息过载、身体还在高唤醒——需要短时卸压，避免拖到彻底垮掉才休息。  
- **WLB 节奏适配**：按脑电与场景判断更贴近「该收 / 该启 / 该卸」的 tempo。  
- **佩戴头带但不主动求助**：落差时刻人未必会打开 App；适时提醒须严苛管控。  
- **碎片可完成**：3～10 分钟内走完一条短训，尽量不打断一天的节奏。

### 核心痛点

- 未完成感、未就绪感、未被察觉的走神与过劳，缺少基于脑状态的、对准 WLB 的短时介入。  
- 冥想 App 多为**被动**，且内容与**当下工作/休息节奏脱节**。  
- 训练视效 / 声景沉浸不足，交互偏单向，难形成愿意重复的 tempo。  
- Soft Healthcare 边界：只能做状态调节，不能做成诊断或治疗宣称。

### Solution（我们怎么做）

1. **对准三类时刻**：真空期调律、工作中回笼专注、工作中卸压——场景化短训 + Session。  
2. **脑电驱动的 tempo**：校准基线 → 判定减压 / 专注倾向 → 推荐更适配的练习节奏（调节式介入，非医疗治疗）。  
3. **Tuno 对话 / 会诊**：理解意图，导向合适练习；专家只拼现成目录。  
4. **沉浸视效 + 声景 + 轻游戏感（进行中）**：同一套「愿意待进去」的氛围工程。  
5. **更可靠的脑电评测与规则（本轮 demo 之外加厚）**：数据训练、评测集与交互规则持续迭代。

一句话：**Attunia = Soft Healthcare 下，对准 WLB 真空期 + 工作中走神/超负荷的脑电调律 + 适时提醒 + 美的短训与 Tuno 陪伴**。

### Success Metrics（成功指标草案）

人话目标：帮助人进入更好的工作状态，并在需要时回到生活侧的调适状态；让人对自己的工作节律与切换感到**更可预期、更好主动调**（不是「控制心流 / 操控大脑」的医疗宣称）。

| 层 | 量什么 | 草案指标 |
|---|---|---|
| **介入频次（主计数）** | 工作时段内有效调节事件 | `unload_from_overload`：从过载卸压的次数；`cultivate_focus`：回笼 / 培养专注的次数；另计 `clock_out_settle`：真空期收束、回归生活的次数 |
| **判定质量** | 状态判得稳不稳 | 窗口判定精确率 / 误报率；用户「说得对 / 不对」轻量反馈 |
| **采纳与完成** | 提醒是否真变成练习 | 提醒→开练率、短训完成率（避免只刷判定次数） |
| **主观可控感** | 节律是否更跟得上 | 「今天切换更顺」「过载时有被接住」等简短自评 |

验证公式（草案）：**成功 ≈（判得够稳的频次）×（人愿意跟练并完成）×（事后感到工作/生活切换更顺）**。  
对外表述落在「更早察觉过载与走神 + 在对的节律点完成调适」，不承诺诊断或心流操控。

- 主路径可演示：开屏 / 设备校准、生活场景短训、Session、Chat、会诊编排。

- **脑电相关已起步**：主动判定规格 + `detectWorkNeed` 雏形；评测有 `eval_No.1`（对话 / 状态 / 危机）与 `eval_No.2`（work windows）切片——可演示判定逻辑，**尚非大规模数据训练后的稳定模型**。
- 后端对话与 TTS；多 Agent 协作基建与 Version=1 已验收切片。

## Remaining Work & Plan（剩余与计划）

1. **主动提醒闭环（真空期 + 走神/超负荷）**：严苛管控下的采样 → 判定 → 非打扰弹窗 / 进短训。  
2. **视效 / 声景 / 轻游戏感**：沉浸美学 + 可玩反馈；声景与音乐制作与视效同级投入。  
3. **（本轮 demo 之后）脑电数据训练 + 更可靠评测集与交互规则**：在现有 eval 切片上扩样本、定规则、降误报。  
4. **任务板收口**：会诊评测、Friends 动效、字幕/脑电开关等按 `board.json` 推进。

## Technical Challenges Encountered（技术难点）

1. **视效 / 动效与轻游戏感（同一问题）**：沉浸美学氛围 + 可玩目标与反馈，和练习节奏同频，避免纯装饰。  
2. **脑电主动提醒的场景与机制必须严苛管控**：冷静期、信号质量门槛、勿扰与误报代价；宁可不打扰，也不能骚扰或伪医疗断言。  
3. **（不在本轮 demo 完成）脑电使用侧的数据训练、更可靠评测集与交互规则**：现有 eval 只是起点；要支撑更稳的判定与产品规则，需后续持续建集与训练。  
4. **音乐 / 声景创作制作**：与视效同一类挑战——为调节时刻提供匹配 tempo 的听觉氛围，质量与内容合规（目录内物料优先，不即兴越界）。
