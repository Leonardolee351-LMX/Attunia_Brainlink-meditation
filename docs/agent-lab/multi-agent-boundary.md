# Multi-Agent 会诊边界（现行）

> 给后端对话、todolist 对话、以及任何问「多专家到底能不能做 X」的人用。  
> 实现代码：`api/agents/user-agent.ts`、`api/agents/consult-stages.ts`。  
> 产品 Agent 对话机制现阶段由**后端**接管，不由前端改语义。

本文替代旧 A2A 的默认假设：**专家不再围着同一个目标抢一张方子。**

---

## 一句话

中枢 Tuno 先判定训练方向和顺序 → 按擅长把**环节**分给专家 → 专家只从**已有疗法目录**里挑模块、调已有参数 → Tuno 拼成一条可练的顺序方案。用户能在会诊记录里看见派工和拼接。

**现在不做：** 创作新练习、生图、作曲、专家多轮互改。

---

## 和旧 A2A 的区别

| | 旧 A2A | 现行 Multi-Agent |
|--|--------|------------------|
| Tuno 在判什么 | 减压/专注/睡前**百分比**，再取一个主目标 | **有序环节**（最多 2 步）+ 每步的目标 |
| 专家在干什么 | 每人出一张完整计划，互相竞争 | 每人只做自己的环节；一个人可以领两步 |
| 结局 | 加权选出**一个**赢家 | 按步**拼接**目录模块（阶段引导词连在一起） |
| 即兴 / 生图 / 作曲 | Sona 可 `invented` | **禁止**。只排列组合已产出物料 |
| 专家互改 | 无（并行提案 + 中枢仲裁） | 仍无。不能协作时由 Tuno 整合。多轮互改是以后的事 |

单 Agent 对话仍走自己的 combo，不经过专家会诊。本边界只管 Multi-Agent / 会诊路径。

---

## 现行允许

- 听「先…再…」：例如先停下工作（减压/下工）再睡前准备。
- 按擅长派工（规则兜底，LLM 可微调，但不得违反「只拼目录」）：
  - 减压 / 允许停下 → Mira（心理咨询）
  - 专注 / 认知卸负荷 → Chen（认知科学）；心流入场 → Kai
  - 睡前 / 生理下行 → Vega（脑科学）
  - 已有声音/意象/引导强度的**点选** → Sona（艺术与创作），仍必须来自目录里那一项已有的 `musicType` / `phases` / `guidanceLevel`
- 同一专家擅长两个环节时，Tuno 可以把两步都交给该专家。
- 参数只允许在目录已有槽位上调：时长（不超过用户可用时间）、该计划已有的呼吸模式、已有 `musicType`、引导强度分档。
- 会诊 transcript 必须让用户看见：顺序、谁负责哪一步、最终如何拼上。
- 规则引擎与 LLM 两条路都要遵守本边界；LLM 若要求即兴，后端必须否决。

## 现行禁止

- **创作新内容**：新练习名、新场景白描、新引导长文、`planId: "invented"`。
- **生图**：不要在会诊里调图像 API，不要为训练现画封面。用目录封面 / 已有交互模块。
- **作曲 / 生成音乐**：不要调 MiniMax 音乐或其他生成接口。只点名目录或六景里**已经有的**声景 / `musicType`。
- **三步及以上**：截成最多两步。
- **专家多轮互相 coding/fix**：不要为了「更像协作」加第二轮 LLM。分歧由 Tuno 一次整合。
- **把脑电原始数据、可识别健康信息**送进任何外部生成 API。
- 前端在页面里重写推荐语义、自己发明一套专家逻辑。

以后要做生图/作曲/即兴/专家互改，必须先改本文并开票；在此之前任何对话都按禁止处理。

---

## 训练任务的四层（现阶段怎么处理）

| 层 | 现阶段 | 以后 |
|----|--------|------|
| 计划（模块、阶段、时长、呼吸） | 目录排列组合 | 仍以目录为主 |
| 引导词 | 只用该模块 `phases[].instruction` | 再考虑改写口播 |
| 音乐 | 点选已有 `musicType` / 场景 BGM | MiniMax 作曲等 |
| 图像 | 已有封面与交互（bloom / ripples / drift） | 生图 |

---

## 问「边界在哪」时怎么答

1. 先读本文，不要用旧 A2A（五专家抢一张方子、Sona 即兴）当现行事实。
2. 会诊产出必须能追溯到目录 `planId`，不能出现 invented。
3. 需要新物料（图、曲、新练习）→ 记「以后」，不要在当期票里做。
4. 改契约形状（例如会诊结果变成两步 `ComboRecommendation`）→ 总控批准 `contracts/`，前端再画；后端可先把两步写进 `decision.customized.phases`。
