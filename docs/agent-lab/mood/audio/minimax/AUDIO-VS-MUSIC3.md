# MiniMax Audio vs Music3 可用性（本机结论）

**日期：** 2026-09-05  
**前提：** 当前 Key 调 `/v1/music_generation` 已被 2153/410 拒（新用户）。

| 路径 | 能否给本项目「API 批量出六景纯音乐」 | 说明 |
|------|--------------------------------------|------|
| **MiniMax Audio**（官网产品页） | **不能当开发 API 用** | 官方给新用户的**体验/网页产品**入口，不是再开一条 `music_generation`。本机 `mmx` + 现 Key 仍打同一套 Music API，已证实失败。可用方式：人在网页上手动生成 → 下载 mp3 → 放进 `public/audio/scenes/`。 |
| **开源 MiniMax-Music3** | **能力上有，本机硬件不够** | HF/GitHub 权重可下；官方服务示例需 **两张 CUDA GPU**（SGLang-Omni）；权重约 **57GB**；本机仅 **GTX 1060 6GB 一张**，无法按官方路径跑通推理。 |

## 对本仓库的实用结论

1. **自动化作曲（脚本/后端）**：当前账号 + 本机 GPU → **不可用**。  
2. **人工出曲**：MiniMax Audio / 其它工具（Suno 等）离线做完再入库 → **可用**，且符合「会诊不现作曲、只点已有物料」。  
3. **继续程序化床轨**：已有 `generate_scene_audio.py` → **可用**，但是音效床不是完整编曲。

## 若以后要跑 Music3

- 至少准备官方要求的多卡 CUDA（或经充分验证的单卡量化方案，官方主路径仍是双卡服务）。  
- 磁盘预留 >60GB 权重。  
- 离线生成后只提交 wav/mp3，不把权重进 git。
