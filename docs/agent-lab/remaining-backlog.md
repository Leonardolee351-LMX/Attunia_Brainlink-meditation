# 剩余 backlog 优先级（比赛切片）

**决策语境：** 当前未交付切片之后的范围排序：先做什么能演示、能验产品、且不砍合规。  
**输入：** 用户给出 5 条剩余工作；任务板现状 F-5 doing、B-1/B-2 review。  
**估算性质：** Reach 无量化数据，RICE 不跑（避免假精度）。Kano 无用户调研，排除。已跑 ICE、MoSCoW、加权评分（估分脚手架，非实测）。

## 适用性过滤

| 框架 | 是否跑 | 原因 |
|---|---|---|
| ICE | 是 | 粗粒度判断足够 |
| MoSCoW | 是 | 需要 Must/Should/Could 承诺 |
| Weighted | 是 | 评委演示 / 产品验证 / 合规 / 工期 多准则 |
| RICE | 否 | 无 Reach 与人周数据 |
| Kano | 否 | 无调研 |

## ICE

Impact / Confidence / Ease 均为 1–10 判断。Ease 高 = 更容易做完。

| Item | Impact | Confidence | Ease | ICE | Notes |
|---|---|---|---|---|---|
| 比赛提供 API 用起来 | 8 | 6 | 6 | 288 | 取决于组委会文档是否已齐；与 F-5 TTS/声景可能重叠 |
| A/B 三组对照 | 9 | 5 | 4 | 180 | 产品性验证强，但要分流、埋点、对照臂，工期不短 |
| 核心 UserFlow 逐帧 UX | 8 | 7 | 5 | 280 | 先审计后改代码；改动面大但路径清晰 |
| 合规体验（免责+危机）不丢 | 9 | 8 | 6 | 432 | 评委与用户安全都敏感；后端已有危机词表缺口（B-2 note） |
| UI 动效加分 | 6 | 7 | 7 | 294 | 无限加分，可与其它票并行小步，不挡主路径 |

ICE 排序：合规 → 动效 → 比赛 API → UserFlow → A/B。动效 Ease 高所以 ICE 偏高，**不能单独当执行顺序**。

## MoSCoW

| Item | Bucket | Rationale | 砍掉的风险 |
|---|---|---|---|
| 合规体验 | Must | 用户明确：保证 UX 的同时不上掉合规 | 危机误导、免责缺失，评委与伦理双杀 |
| 比赛提供 API | Must | 赛题资源不用等于交白卷 | 加分项与技术完整性不足 |
| A/B 三组对照 | Should | 验证产品性，不是最小演示路径 | 说不清「记忆/脑电/LLM」各自贡献 |
| 核心 UserFlow UX | Should | 体验决定留存与演示流畅 | 流程能跑但像原型 |
| UI 动效 | Could | 无限加分，不设完工线 | 只少一层质感，功能仍在 |

## 跨框架对照

| Item | ICE 名次 | MoSCoW | 加权名次 | 一致性 |
|---|---|---|---|---|
| 合规体验 | 1 | Must | 1 | 强 |
| 比赛 API | 3 | Must | 2 | 强（Must 优先于 ICE 第三） |
| UserFlow UX | 4 | Should | 3 | 强 |
| A/B 三组 | 5 | Should | 4 | 强；ICE 最低因 Ease |
| UI 动效 | 2 | Could | 5 | **发散**：ICE 因好做偏高，MoSCoW/加权都垫底 |

**发散结论：** 动效不要按 ICE 插队。A/B 不要因难而砍，排在两条 Must 和 UX 审计之后开契约。
